# v0.3 part 3: Plot builder and insight plots: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner build a plot from his transactions in a few choices, save it as a panel on any tab, and add ten ready-made insight plots, with numbers that agree with the rest of the app.

**Architecture:** A plot is data: a `PlotSpec` (what is measured, along which axis, split by what, over which period, drawn how). One backend read, `plot_query`, turns a spec into series using the same spending rules as Trends. One UI component draws any spec; saved plots live in the saved layout and appear as panels with ids `plot:<id>`. The builder is a popup that edits a spec with a live preview.

**Tech Stack:** Rust; `finance-core` over the cached snapshot; Leptos 0.8 CSR (WASM); the house SVG charts in `app/ui/src/ds/charts.rs`; no new dependency.

**Spec:** `docs/superpowers/specs/2026-11-24-layout-and-plots-design.md`, phases 3 ("Plots") and 4 ("Insights"), done as one plan. Builds on `2026-11-24-v03-cleanup-and-fold.md` and `2026-11-24-v03-arrange.md`, both merged first.

## Global Constraints

- A plot's numbers agree with the app: spending is `budget::spending_transactions(ctx, payments)` (as `dashboard.rs` builds it), outflows minus refunds (`forecast::signed`), own transfers out, transactions dated after now ignored, the day is `purchased_on` or the local booking day (as `trends::local_day`). "Variable only" and the axis "Fixed against variable" use `groups::non_variable_ids` with the same `fixed_categories` `dashboard.rs` builds. "Budget months" uses `ctx.resolver.month_of(t)`.
- Money is `Decimal` end to end on the backend, rounded with `trends::cents` where a division happens. `f64` only for chart geometry in the UI (`pages::f`).
- One currency per plot: `spec.currency`, else the main currency (the first of `report.time_trends.currencies`, as the pages do).
- `PlotSpec` is saved JSON: every field has a serde default, so a spec saved by an earlier build still loads; unknown enum values make that one plot show "This plot can't be drawn" instead of failing the layout.
- Same look as today: charts follow the existing charts' grid, ticks, tooltip, legend and the `--ds-chart-1..6` palette plus `fixed`, `free`, `limit`. A plot never draws more than six series; the rest are "Other". New UI parts are `ds` components; class constants are role-named in `ds/patterns.rs`.
- The unfinished current bucket (this month, this week, today) is drawn lighter and is never named highest or lowest.
- Every command exists in `app/src-tauri/src/main.rs` (and `generate_handler!`) and `app/devserver/src/main.rs`.
- No new dependency. Tests cover calculations and writes, not wording or layout of screens.
- `cargo` is not on PATH: `export PATH="$HOME/.rustup/toolchains/1.99.1-aarch64-apple-darwin/bin:$PATH"`; do not set `CARGO_TARGET_DIR`. Never run the devserver without `DEV_DB`.
- CI commands green before each commit (see `.github/workflows/ci.yml`): fmt check, the two clippy sets with `-D warnings`, the non-UI tests, `cargo test --locked -p finance-ui --bins`.
- Commit messages end with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Review Focus

1. **A period with no transactions, or a ledger with none**: the plot shows an empty state ("Nothing in this period"), `plot_query` returns zero series without dividing by zero; averages of nothing are absent, not 0. Test in Task 2.
2. **A split or axis with hundreds of values** (278 merchants in six months on the real ledger, 215 seen once): top N plus "Other", and "Other" plus the named ones sums to the total. Test in Task 2.
3. **Refunds larger than spending in a bucket** (a negative bar), and a category whose net is negative: bars draw below zero, donut and ranked leave out non-positive values and say so in the subtitle. Test in Tasks 2 and 5.
4. **A saved plot whose spec this build cannot read, or whose filter names a category that no longer exists**: that panel shows its own message; other panels and the layout are untouched; the filter simply matches nothing. Test in Tasks 1 and 4.
5. **A custom period typed backwards or absurdly long** (from after to; 30 years by day): `validate` refuses from > to; a day axis longer than 366 buckets, a week axis longer than 260 and a month axis longer than 240 are refused with a message that names the limit. Test in Task 1.

Rules for `validate` (each an Err with a short reason): 1 to 3 measures; more than one measure only when `split` is None; `Chart::Scatter` needs exactly two measures and no split; `Donut` and `Ranked` need a named axis, one measure and no split; `Heatmap` needs a split and one measure; `StackedBars` needs a split or 2+ measures; `Value::Change` needs a named axis or a time axis and `compare == None`; `cumulative` needs a time axis; `Compare != None` needs a time axis and no split; `top` in 1..=20 and `split_top` in 1..=6; `Between`: both dates parse, from <= to; bucket limits Day 366, Week 260, Month 240 over a `Between` period; `split` may not equal the axis (Weekday/Weekday, Year/Year, Category/Category…). `charts()` returns exactly the charts for which `validate` would pass with that chart, given the other fields. `UiLayout::validate` gains: at most `MAX_PLOTS` plots, unique plot ids, titles 1..=`MAX_NAME` chars.

### Task 2: `plot_query`, the plain cases

**Files:**
- Create: `crates/core/src/plot.rs`, `crates/core/src/plot_tests.rs`
- Modify: `crates/core/src/lib.rs`, `crates/core/src/service.rs`

**Interfaces — produces:** `pub fn plot_query(ctx: &Ctx<'_>, spec: &PlotSpec) -> crate::Result<PlotData>` and `Service::plot_query(&self, spec: PlotSpec) -> Result<PlotData, String>` (a `read`). This task implements everything except `period_basis: Budget`, `cumulative`, `compare`, `average_line`, `Value::Change`, `Measure::AveragePerDay` and `insight` (Task 3); those return their plain result or `None` for now.

Decisions:
- Rows: `budget::spending_transactions` for `Outflow` and `Refund`; `Inflow` rows from the same list for Income and Net. Each measure over a bucket: Spent = Σ signed; Income = Σ inflow amounts; Net = Income − Spent; Count = number of outflows; Average = Spent ÷ Count, `cents`, absent when Count is 0; Largest = the largest single outflow, absent when none.
- Buckets: every bucket in the period exists, in order, with `Some(0)` for sums and counts when empty (`None` only for Average and Largest). Time axis labels: Day `24 Nov`, Week `17 Nov` (its Monday), Month `Nov`, with the year appended (`Nov 2025`) when the period spans more than one year; Quarter `Q4 2026`; Year `2026`. `titles` carry the long form for tooltips. Weekday is Monday to Sunday; DayOfMonth 1 to 31.
- Periods (calendar): ThisMonth = the 1st to today; LastMonth = the previous full month; Last3/6/12Months = the current month and the 2/5/11 before it (Last6Months is the window `time_trends` uses); ThisYear = 1 Jan to today; AllTime = the first counted transaction to today.
- Named axis: items ranked by the first measure's value, largest first; the first `top` are kept, the rest summed as "Other" (last); `left_out` is how many went into "Other". Split: values ranked by their total over the period; the first `split_top` kept, the rest "Other".
- Merchant: key `writes::review::normalize_merchant(counterparty_name)`, label the most frequent original spelling of that key, missing name → "Unknown". Group: through `groups::group_index`; a category with no group → "No group"; no category → "Uncategorised". Account: the account's name.
- Filters: all given filters must match; `merchant` is a case-folded contains on the normalised key; `min`/`max` apply to a single transaction's amount; `variable_only` drops `non_variable_ids`. A filter naming something that does not exist matches nothing.
- `partial_last` is true when the last time bucket contains today and is not finished. `subtitle` says the period, the basis and "variable only" when set, for example "Last 6 months · calendar months · all spending".
- `unit` is Count when every measure is Count, else Money.

### Task 3: `plot_query`, the options and the insight

**Files:** `crates/core/src/plot.rs`, `crates/core/src/plot_tests.rs`

Decisions:
- `PeriodBasis::Budget`: a transaction's month is `ctx.resolver.month_of(t)`; Month, Quarter and Year buckets and the month-based periods use it ("ThisMonth" = `ctx.current_month()`); Day, Week, Weekday and DayOfMonth buckets still use the transaction's own day.
- `Measure::AveragePerDay`: Spent of the bucket ÷ the number of calendar days of that bucket that lie inside the period and are not after today (for Weekday: the number of such weekdays in the period), `cents`.
- `cumulative`: each series becomes its running sum along the time axis.
- `Compare::Previous`: adds one `reference` series "Period before" holding the same measure over the period of equal length immediately before, bucket for bucket. `Compare::AverageOf3`: a `reference` series "Usual" holding, per bucket position, the mean of the three periods before (`cents`); with `cumulative`, the reference is the running sum too.
- `average_line`: a `reference` series "Average" with the mean of the finished buckets in every position.
- `Value::Change`: each value becomes value − the same item's value over the period of equal length before; named axis items are then ranked by the size of the change; time axis buckets show bucket − previous bucket.
- `insight`, picked by shape, never using the unfinished bucket as "last", "highest" or "lowest":
  - time axis, no compare: `LastAgainstAverage` — label the last finished bucket, value its amount, against the mean of the other finished buckets; absent with fewer than three finished buckets.
  - named axis: `LargestShare` — label the largest item, value its amount, against the total of positive items.
  - Weekday or DayOfMonth: `PeakAgainstLowest` — label the peak, value its amount, against the lowest positive one.
  - any compare: `AgainstPrevious` — label "This period", value the total so far, against the reference's total over the same finished positions.
  `text` is one plain sentence built from those numbers with `format_money`-style formatting already in core (for example "October: €1,420.00, 19% above your average of €1,193.00"); percentages are whole numbers.
