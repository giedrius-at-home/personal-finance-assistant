# v0.3 part 2: Edit layout and your own tabs: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In an "Edit layout" mode, let the owner remove, add back, reorder and resize panels, move them between tabs, and make, rename, reorder, hide and delete tabs, with two resets.

**Architecture:** Every edit is a pure function over the saved `UiLayout` (tested natively); `LayoutState` applies it to its signal and saves through the existing queue. The tab bar is rendered from the layout instead of the fixed `Tab::ALL`. The edit controls, the add-a-panel gallery, the tab editor and the drag-to-reorder helper are design-system parts.

**Tech Stack:** Rust; Leptos 0.8 CSR (WASM, Trunk, Tailwind 4); browser drag events through `web-sys` (features already enabled); no new dependency.

**Spec:** `docs/superpowers/specs/2026-11-24-layout-and-plots-design.md`, phase 2 ("Arrange"). Builds on `docs/superpowers/plans/2026-11-24-v03-cleanup-and-fold.md`, which must be merged first.

## Global Constraints

- Same look as today: only parts from `app/ui/src/ds` and tokens from `app/ui/styles`. No new colours, type sizes, radii or shadows.
- Every new piece of UI is a component or role-named constant in `app/ui/src/ds` (`ds/patterns.rs` for class constants; never named for looks). Pages do not gain layout code.
- No new dependency.
- Outside Edit layout nothing new is visible: no grips, no remove buttons, no tab "+".
- Nothing can be lost: a removed panel is in "Add a panel"; "Reset this tab" and "Reset everything" restore the shipped layout. Manage can be neither hidden nor deleted.
- Saving goes through `LayoutState`'s queue only; it never touches `AppState::revision`; after a failed initial read nothing is saved (existing rule).
- Read page state with `use_context` (never `expect_context`) in anything a movable panel runs.
- Tests cover calculations and writes, not wording or layout of screens.
- `cargo` is not on PATH: start each build shell with `export PATH="$HOME/.rustup/toolchains/1.99.1-aarch64-apple-darwin/bin:$PATH"`. Do not set `CARGO_TARGET_DIR`.
- CI commands, all green before each commit: `cargo fmt --all --check`; `cargo clippy --locked -p finance-types -p finance-storage -p finance-core -p finance-migrate -p finance-secrets -p finance-bank -p finance-notify -p finance-timesfm -p finance-ai -p finance-devserver --all-targets -- -D warnings`; `cargo clippy --locked -p finance-ui --target wasm32-unknown-unknown -- -D warnings`; `cargo test --locked -p finance-storage -p finance-types -p finance-core -p finance-bank -p finance-notify -p finance-timesfm -p finance-ai`; `cargo test --locked -p finance-ui --bins`.
- Never run the devserver without `DEV_DB`.
- Commit messages end with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Review Focus

1. **A link to a hidden tab** (24 call sites use `AppState::go`, `go_spending`, `go_manage`): it opens the tab anyway and the tab shows in the bar while it is open. Test in Task 2.
2. **Deleting the tab you are on, or hiding it**: the app moves to the first visible tab; it never shows an empty screen. Test in Task 2.
3. **A panel on a tab that is not its home, whose page state is absent**: it renders (or draws nothing), never panics. Covered by the `use_context` rule; manual check in Task 5 by adding every movable panel to an own tab.
4. **Dragging with the keyboard only**: every reorder and move is possible without a pointer ("Move up", "Move down", and adding from the gallery on the other tab). Manual check in Task 5.
5. **An own tab named like a built-in one, or with only spaces**: spaces are trimmed, an empty name is refused, duplicates of names are allowed (ids are what must be unique). Test in Task 1.

```rust
/// Where a page lives: its tab id and name, and the page id.
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct PageRef { pub tab: String, pub tab_name: String, pub page: String }

pub fn panel_removed(l: &mut UiLayout, at: &PageRef, panel: &str);              // out of items; into `removed` when the page is the panel's home
pub fn panel_added(l: &mut UiLayout, at: &PageRef, panel: &str);                // appended, open; out of `removed`; no-op when already there
pub fn panel_moved(l: &mut UiLayout, at: &PageRef, panel: &str, to: usize);     // `to` is the index in the list after removal; clamped
pub fn panel_half_set(l: &mut UiLayout, at: &PageRef, panel: &str, half: bool);
pub fn panel_sent(l: &mut UiLayout, from: &PageRef, to: &PageRef, panel: &str); // removed from `from`, added to `to`; refused (no change) when the def is not movable
pub fn addable(l: &UiLayout, at: &PageRef) -> Vec<&'static PanelDef>;           // home defs not on the page, then movable defs of other pages not on the page, registry order

pub fn tab_added(l: &mut UiLayout, name: &str) -> Result<String, String>;       // returns the new id "own-<n>", n = smallest unused; trims; refuses empty or > MAX_NAME; page id "own-<n>"
pub fn tab_renamed(l: &mut UiLayout, id: &str, name: &str) -> Result<(), String>; // own tabs only
pub fn tab_deleted(l: &mut UiLayout, id: &str);                                 // own tabs only; a built-in id is a no-op
pub fn tab_hidden_set(l: &mut UiLayout, id: &str, hidden: bool);                // built-in tabs only; "manage" is a no-op
pub fn tab_moved(l: &mut UiLayout, id: &str, to: usize);                        // index in the full ordered list
pub fn page_reset(l: &mut UiLayout, at: &PageRef);                              // drops the saved page entry
pub fn all_reset(l: &mut UiLayout);                                             // `UiLayout::default()`

/// The tab bar: saved tabs in saved order, then each built-in tab that is not saved, inserted after the nearest earlier built-in (default order) that is present.
pub fn tabs(l: &UiLayout) -> Vec<TabView>;
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct TabView { pub id: String, pub name: String, pub built_in: bool, pub hidden: bool }
pub const BUILT_IN: [(&str, &str); 7];  // ("overview","Overview"), ("transactions","Transactions"), ("spending","Spending"), ("plan","Plan"), ("wishes","Wishes"), ("events","Events"), ("manage","Manage")
```

`resolve` gains a second kind of known id: an item whose panel is not a home def is kept when the registry knows it and it is movable (today such an item is dropped). On an own tab's page there are no home defs, so only saved items show.

**Interfaces:**
- Consumes: Task 1 functions.

```rust
// layout/mod.rs
impl LayoutState {
    pub fn editing(&self) -> ReadSignal<bool>;
    pub fn set_editing(&self, on: bool);
    pub fn edit(&self, f: impl FnOnce(&mut UiLayout));   // applies, then saves through the queue (same Load rules as toggle)
    pub fn save_failed(&self) -> ReadSignal<bool>;       // true after a save returned Err; cleared by the next Ok
}
// ds/arrange.rs
#[component] pub fn EditBar(/* grip, Move up, Move down, Half/Full, Remove; each a Callback; `first`/`last` disable the moves */) -> impl IntoView;
#[component] pub fn Gallery(items: Signal<Vec<(String, String)>> /* (id, title) */, on_add: Callback<String>) -> impl IntoView;  // the dashed "Add a panel" box
#[component] pub fn Confirm(#[prop(into)] label: String, #[prop(into)] question: String, on_yes: Callback<()>) -> impl IntoView; // a button that asks once inline: question, "Yes", "Cancel"
/// Where a dragged item lands: `over` is the item under the pointer, `after` whether the pointer is past its middle. Indexes are positions in the list before the move; the result is the `to` for `panel_moved`.
pub fn drop_index(from: usize, over: usize, after: bool) -> usize;
```

Behaviour:
- "Edit layout" is a `Button` (`Variant::Secondary`, `Size::Sm`) at the right end of the tab bar row; its label is "Done" while editing. Esc leaves edit mode.
- While editing, each `PanelFrame` shows `EditBar` in its header row (open and folded alike), and is `draggable` by the grip only. Dropping on another frame calls `panel_moved` with `drop_index`. The frame under the pointer shows the existing drop highlight (`ring-2 ring-accent/50`, as `BoardColumn` does).
- A panel whose `shown` is false draws, while editing, a one-line muted row with its title and "Nothing to show now", with the same `EditBar`.
- Below the list while editing: `Gallery` fed by `addable`; then "Reset this tab" (`Confirm`, question "Put this tab back as it shipped?").
- When `save_failed`, one line under the tab bar while editing: "Could not save the layout. Your changes are kept until you close the app." (role `alert`).
- Outside edit mode nothing of the above is in the DOM.
